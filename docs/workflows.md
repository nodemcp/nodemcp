# Real workflows and practical examples

The best first demo of remote MCP is small, concrete and easy to verify:

- **[Actual Ubuntu diagnostics](https://nodemcp.dev/demo/)** — three real read-only tool calls with sanitized system results and no changes to the device.
- **[Diagnosing Linux server failures](https://nodemcp.dev/use-cases/diagnose-linux-server-failures-with-ai/)** — a useful process for investigating service state before choosing any repair.
- **[Explore the use-case library](https://nodemcp.dev/use-cases/)** — practical scenarios spanning Linux, Windows, macOS, office work, video and everyday tasks.

A recommended pattern is: **observe → explain → propose → request approval → change → verify**. Tool availability and safe execution depend on the permissions you grant.

Please distinguish a published example from a live on-demand device session. Never paste private server addresses, credentials or production data into a public issue.
